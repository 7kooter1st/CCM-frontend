# GitHub Pages + локальный бэкенд

Чтобы фронт на **https://7kooter1st.github.io/CCM-frontend/** получал данные с **вашего локального** бэкенда (например localhost:8000), нужно выполнить три вещи: включить HTTPS на бэкенде, указать его URL при сборке фронта и разрешить CORS.

---

## 1. Почему бэкенд должен быть по HTTPS

Страница на GitHub Pages открывается по **HTTPS**. Браузер не разрешает такой странице делать запросы на **HTTP** (mixed content). Поэтому запросы на `http://localhost:8000` с https://7kooter1st.github.io будут блокироваться.

**Вывод:** локальный бэкенд должен отдавать API по **HTTPS** (например `https://localhost:8000`).

### Как включить HTTPS на локальном бэкенде (Go/Gin)

Вариант с **mkcert** (локально доверенный сертификат):

1. Установить mkcert и создать CA и сертификат:
   ```bash
   mkcert create-ca
   mkcert create-cert
   ```
2. В коде бэкенда запускать сервер с TLS, используя `cert.pem` и `key.pem` (или имена, которые выдал mkcert).
3. В браузере один раз открыть `https://localhost:8000` и принять предупреждение о сертификате (для mkcert после `mkcert -install` предупреждения обычно нет).

Если бэкенд уже умеет читать сертификаты из файлов — достаточно указать пути к ним. Если нет — в документации Gin есть пример запуска с TLS.

---

## 2. Указать URL бэкенда при сборке фронта

Фронт при сборке для GitHub Pages подставляет URL API из переменной **`VITE_API_URL`**.

**Шаг 1.** В корне фронта (рядом с `package.json`) создайте файл **`.env.gh-pages`** (без .example):

```bash
# Для локального бэкенда по HTTPS на порту 8000:
VITE_API_URL=https://localhost:8000
```

Если бэкенд слушает на другом порту или хосте — подставьте свой URL, например:

```bash
VITE_API_URL=https://127.0.0.1:8080
```

**Шаг 2.** Соберите и задеплойте фронт (см. раздел 4).

---

## 3. CORS на бэкенде

Сервер должен разрешать запросы с источника **https://7kooter1st.github.io**.

В Gin обычно достаточно настроить CORS так, чтобы разрешённый origin был `https://7kooter1st.github.io` (или все origins в разработке). Убедитесь, что в ответах есть заголовок `Access-Control-Allow-Origin` для этого origin.

---

## 4. Как применить изменения фронта на GitHub Pages

После **любых** изменений во фронте (код, стили, `.env.gh-pages` и т.п.), чтобы они попали на GitHub Pages:

1. В корне проекта фронта выполните:
   ```bash
   npm run deploy
   ```
   Эта команда:
   - запускает `npm run build:pages` (сборка в режиме `gh-pages`, с подстановкой `VITE_API_URL` из `.env.gh-pages`);
   - пушит содержимое папки `dist` в ветку `gh-pages` репозитория.

2. Подождите 1–2 минуты, пока GitHub обновит сайт.

3. Откройте **https://7kooter1st.github.io/CCM-frontend/** (лучше с жёстким обновлением Ctrl+F5), чтобы подтянуть новый фронт.

Итого: **после каждого изменения фронта выполняйте `npm run deploy`** — тогда эти изменения появятся на GitHub Pages.

---

## 5. Проверка

1. Запустите бэкенд **по HTTPS** на том адресе, который указан в `VITE_API_URL` (например `https://localhost:8000`).
2. Убедитесь, что в браузере запросы к этому URL не блокируются (при необходимости примите сертификат).
3. Откройте https://7kooter1st.github.io/CCM-frontend/ на **том же компьютере**, где запущен бэкенд.
4. В DevTools (F12) → Network должны быть запросы к вашему локальному API (например `https://localhost:8000/api/usecases/`), а на сервере — соответствующие логи запросов.

Если запросы не уходят или блокируются — проверьте консоль и вкладку Network на наличие ошибок mixed content или CORS.
