# Развёртывание на GitHub Pages и PWA

## Нужно ли что-то запускать на ПК?

**Нет.** GitHub Pages — это хостинг статики на серверах GitHub. После `npm run deploy` сайт работает без вашего компьютера. Ни сервер, ни приложение на ПК для открытия страницы с телефона или другого устройства запускать не нужно.

---

## 1. GitHub Pages

### Подготовка

- **Имя репозитория** на GitHub и константа **`GITHUB_PAGES_BASE`** в `vite.config.ts` должны совпадать **буква в букву** (включая регистр). Сейчас задано **`/consumption-manager`**. Если репозиторий называется иначе (например **`CCM-frontend`**), измените в `vite.config.ts`: `const GITHUB_PAGES_BASE = '/CCM-frontend'` (или ваше имя репо).
- В настройках репозитория: **Settings → Pages → Source**: Deploy from a branch. Ветка — **`gh-pages`**, папка — **/ (root)**.

### Деплой

```bash
npm run deploy
```

Скрипт соберёт проект в режиме `gh-pages` (база `/consumption-manager/`) и опубликует содержимое папки `dist` в ветку `gh-pages`. После этого сайт будет доступен по адресу:

**https://&lt;ваш-username&gt;.github.io/consumption-manager/**

Открыть с телефона: тот же URL в браузере (желательно по HTTPS).

### Ошибка «MIME type text/html» и пустая страница

Если в консоли браузера видно, что загрузка скрипта заблокирована из‑за MIME-типа («text/html»), по адресу `.../assets/index-xxx.js` приходит не JS, а HTML (обычно страница 404). Значит, путь к файлам не совпадает с тем, как раздаёт их GitHub.

**Что сделать:**

1. Откройте репозиторий на GitHub и посмотрите **точное имя репозитория** (вверху страницы, в URL: `github.com/7kooter1st/**имя-репо**`).
2. В `vite.config.ts` задайте `GITHUB_PAGES_BASE` **строго по имени репо**:
   - репо `consumption-manager` → `const GITHUB_PAGES_BASE = '/consumption-manager'`;
   - репо `CCM-frontend` → `const GITHUB_PAGES_BASE = '/CCM-frontend'`.
3. Заново выполните сборку и деплой:
   ```bash
   npm run deploy
   ```
4. Открывайте сайт по адресу **https://7kooter1st.github.io/&lt;имя-репо&gt;/** (то же имя, что в `GITHUB_PAGES_BASE`).

После деплоя можно проверить: откройте в браузере `https://7kooter1st.github.io/<имя-репо>/assets/` — не должно быть 404; в ветке `gh-pages` на GitHub должны быть папка `assets/` и файлы в ней.

## 2. PWA (Progressive Web App)

- Включён **vite-plugin-pwa**: есть manifest и Service Worker с автообновлением.
- Иконки: `public/icon-192.png` и `public/icon-512.png` (сейчас — копии заглушки; при желании замените на свои 192×192 и 512×512).
- После деплоя на GitHub Pages в браузере на телефоне можно нажать «Добавить на главный экран» / «Установить приложение» — появится иконка и запуск без панели браузера.
- Офлайн-работа: после первой загрузки часть ресурсов кешируется; при отключении сети можно продолжать пользоваться уже открытыми разделами.

---

## 3. Адаптивность

- Сетка карточек сценариев подстраивается под ширину экрана (1–4 колонки).
- В шапке на узких экранах (≤545px) ссылки «Домой» и «потребление» скрыты и показывается бургер-меню; по нажатию открывается выпадающее меню.

---

## Замечание по API

На GitHub Pages бэкенд не разворачивается. Запросы к API в браузере идут на тот же origin (через прокси в dev или на ваш сервер, если вы его настроите). Для работы с данными с телефона нужен доступный по HTTPS бэкенд и при необходимости правка `api_proxy_addr` / логики в коде под прод.

Методические указания: [PWA.md](https://github.com/iu5git/Web/blob/main/tutorials/pwa/PWA.md)
